## Goal
The same game, but it feels good. The phase that decides whether the project was worth doing.

## Runnable outcome
Breaking a brick is satisfying on its own.

## Tasks (PLAN Phase 4)
1. `src/render/particles.rs` — fixed-capacity particle pool (no per-frame allocation); velocity, gravity, lifetime, colour ramp (FR-24).
2. `src/render/camera.rs` — screenshake as decaying sub-pixel offset, magnitude by event class (FR-25).
3. Hit-stop in the simulation loop, scaled down by combo (FR-26). Sim freezes, render continues (ADR-0006).
4. Ball trail from ring buffer of positions, drawn additively (FR-27).
5. Brick and paddle hit flashes (FR-28).
6. `src/render/bloom.rs` — threshold + 3×3 blur + additive composite; toggle `F4` / `--no-bloom` (FR-29). Must stay inside NFR-1 at default scale.
7. Combo counter scale-pop and colour ramp (FR-30).
8. Lock palette from MOCKUP.md into `src/render/palette.rs` as named constants.

## Test gate
```sh
cargo run --release
cargo run --release -- --no-bloom
```
Play a level with debug overlay on.

## Pass when
p99 frame time still ≤ 16.6 ms with bloom on, 200+ live particles and screenshake active (NFR-1); bloom off shows a visible frame-time saving recorded in `docs/PERF.md`; the game visually matches `mockup.html` closely enough that palette, proportions and HUD placement are recognisably the same design.

## Stop rule
Mike looks at it side by side with the mockup and says it is close.

## Not in this phase
New gameplay mechanics. Juice only.

## Spec source
MOCKUP.md §2 (palette) and §4 (effect specs) are normative — values go into `palette.rs` / render modules verbatim.
