## Goal
The program can take over the terminal and give it back, and can tell you what the terminal can do. No game yet.

## Runnable outcome
- `breakout --caps` prints a capability report and exits 0.
- `breakout` enters alt screen, shows a placeholder text frame, and `q` returns to a clean prompt.

## Tasks (PLAN Phase 0)
1. `cargo new --bin breakout-tui` at `$REPO`; `Cargo.toml` with `[[bin]] name = "breakout"`, `path = "src/main.rs"`, `rust-version` (MSRV = 1.98). `rust-toolchain.toml` channel = 1.98 (exact).
2. Add exactly the deps in ADR-0005. No others.
3. Module skeleton from ADR-0005 §Layout; every module compiles with `todo!()` bodies.
4. `src/term/guard.rs` — RAII `TerminalGuard` (raw mode, alt screen, hide cursor, push keyboard flags on construct; reverse + `\x1b_Ga=d,d=A,q=2\x1b\\` on Drop). Panic hook + SIGINT/SIGTERM clean shutdown (NFR-4, FR-5).
5. `src/term/caps.rs` — probe graphics protocol (`\x1b_Gi=31,s=1,v=1,a=q,t=d,f=24;AAAA\x1b\\`, 200ms wait), keyboard (`\x1b[?u`), cell/window pixel size (TIOCGWINSZ → CSI 14t/16t), terminal identity.
6. `src/cli.rs` — exact flag set in PRD FR-3. `--caps` prints report, exits 0.
7. Implement FR-4: no graphics support → message + exit 2.

## Test gate
```sh
cargo build --release
cargo clippy --all-targets -- -D warnings
cargo fmt --check
./target/release/breakout --caps
./target/release/breakout          # placeholder; press q
BREAKOUT_PANIC_TEST=1 ./target/release/breakout ; stty -a | head -1
./target/release/breakout & sleep 1 ; kill -INT %1 ; wait
TERM=dumb ./target/release/breakout ; echo "exit=$?"   # expect exit=2
```

## Stop rule
Do not start Phase 1 until you have typed in the terminal *after* each of the three failure paths and seen normal echo.

## DoD
- Runs in Ghostty on macOS.
- `cargo test`, `cargo clippy --all-targets -- -D warnings`, `cargo fmt --check` clean.
- `TerminalGuard` restores terminal after forced panic (`BREAKOUT_PANIC_TEST=1`) — re-check every phase.
- No new runtime dep without an ADR.
